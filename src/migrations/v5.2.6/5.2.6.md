## Manage Tray register (light DB)

- Columns: `type`, `packing_number`, `link_count`, `data`, audit (`tray_code` column drop → **5.2.7**).
- `data` = **`{ links: [...] }` only** (sticker, tray, qty, from; receive `acc` / `cust` / `out`).

- **Item codes not stored** — join stickers → box → dailyprod for list/detail.
- Backfill strips `item_codes` / `qtys` / `total_qty` / type / packing keys from JSON.
- Do not use jsonb `?` in SQL (db layer → `$1`); use `jsonb_exists` or `data - 'links'`.

## Register UI

- **Pending:** New only.
- **Register:** View / Edit / Delete (permission).
- Assign / Reassign / Receive all editable.
- Receive edit: FG customer trays; remove restores tray↔box.
- Column **Trays** = link count.

## IMS = FG only

- List / report / scan = **FG** trays.
- **PRD** → Production app message.
- Types: **FG / RM / PRD**. App name **PROD** ≠ tray type.
